# Human-Readable Writing

Write repository prose for human readers. These rules are inspired by ASD-STE100
(Simplified Technical English). They do not claim full compliance with it.

Apply these rules to all repository prose: documentation, skills, code comments,
user-facing messages, PR descriptions, and review comments.

## Write short sentences

Write short sentences with one main idea each. Split long sentences into separate
sentences.

## Use active voice

Use active voice. State who does what. Use passive voice only when the actor is
unknown or unimportant.

## Use consistent terms

Use consistent terms for the same concepts. Do not vary wording for style.

## Prefer concrete statements

Prefer concrete statements over vague claims. State what happens, who does it, and
what the result is.

## Group related details

Use bullets and short sub-bullets to group related details. Avoid dense paragraphs
and deep nesting.

## Include only useful details

Include only details that help the reader understand or act. Omit routine
housekeeping and background the reader does not need.
